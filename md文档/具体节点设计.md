# 具体节点设计

本文档把 `剧情.md` 拆成可配置到 `StoryNodeSO` 的具体节点。节点编号统一使用 `int` 类型。CG 当前暂时统一写 `kong`，表示空。

## 立绘编号

- `-1`：不显示立绘
- `0`：小明
- `1`：父亲
- `2`：母亲
- `3`：陈爷爷 / 陈工
- `4`：陈奶奶
- `5`：陈春柏
- `6`：高中历史老师
- `7`：卫生所年轻医生
- `8`：疯疯癫癫的道士
- `9`：村民群像
- `10`：旁白
- `11`：树神 / 古神

## 道具与 Flag 命名建议

- 道具：`宝树果实`、`大白兔奶糖`、`水井里的锈剑`、`一把铜钥匙`、`一把铁钥匙`、`不知名丹药`、`医生的笔记`、`一瓶酒`、`一瓶药`、`揉皱的小广告`、`一封信`、`红糖糕`
- Flag：`FLAG_TOLD_FATHER`、`FLAG_HIDE_TRUTH`、`FLAG_GOT_DOCTOR_MEDICINE`、`FLAG_FINAL_TREE_WEAKENED`、`FLAG_TREE_MEMORY_BROKEN`

## 配置注意事项

- `节点编号` 和 `下一节点` 均使用 int。`0` 表示无下一节点或结局结束。
- 顺序节点把 `下一节点` 填到 `nextNodeID`。
- 分支节点的 `下一节点` 填 `0`，具体跳转写在 `分支设置` 中。
- `CG（默认为空）` 当前全部写 `kong`，实际创建 SO 时可先留空。
- `道具需求` 用于 `requiredClue` 或 `requiredFlag`。
- `道具奖励` 用于 `rewardClue`。

## 自动生成工具格式要求

`Tools > Generate Story Nodes From Design` 会按本文件的 Markdown 表格生成 `StoryNodeSO`。为了让工具稳定解析，表格内容请遵守以下格式：

- 每个剧情节点必须是一行标准表格，且列顺序保持为：`节点编号 | 节点对话人名称 | 节点内容 | 对应人物编号 | CG | 道具需求 | 下一节点 | 分支设置 | 道具奖励`。
- `节点编号` 和 `下一节点` 必须是 int。没有下一节点时写 `0`。
- 没有内容的字段统一写 `无`，CG 为空时统一写 `kong`。
- 普通顺序节点：`分支设置` 写 `无`，`下一节点` 写目标节点编号。
- 分支节点：`下一节点` 写 `0`，`分支设置` 使用固定格式：`A：选项文本 -> 目标节点，需求=\`线索名\`，flagOnChoose=\`FLAG_NAME\`；B：选项文本 -> 目标节点`。
- 选项需求是线索时写 `需求=\`一封信\``；选项需求是剧情标记时写 `需求=\`FLAG_HIDE_TRUTH\``。
- 当前 `StoryChoice` 只支持一个 `requiredClue` 和一个 `requiredFlag`。如果设计里写了多个线索需求，例如 `需求=\`一瓶酒\` + \`水井里的锈剑\``，自动生成时只会稳定写入第一个线索，完整多道具判断需要后续扩展 `StoryChoice`。
- 进入节点写入 flag 时，在 `分支设置` 中写：`flagOnEnter=\`FLAG_NAME\``。
- 结局节点在 `分支设置` 中写：`isEnding=true，endingType=TrueEnding`、`isEnding=true，endingType=NormalEnding` 或 `isEnding=true，endingType=BadEnding`。
- `道具奖励` 必须和 `Assets/SOS/线索SO` 中对应 `ClueSO.clueName` 完全一致，否则工具无法自动绑定 `rewardClue`。
