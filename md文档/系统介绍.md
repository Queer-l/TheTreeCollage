# 系统介绍

## 剧情系统如何运行

当前项目的剧情系统由 `StoryNodeSO` 提供剧情数据，由 `StoryManager` 负责运行和显示剧情，由 `PlayerData` 保存玩家的剧情进度、已解锁线索和剧情标记。

整体流程是：

1. 在 Project 面板中创建多个 `StoryNodeSO` 剧情节点资产。
2. 每个节点填写对话文本、说话人、CG、人物立绘索引、奖励线索和分支选项。
3. 大部分按顺序播放的剧情，通过节点里的 `nextNodeID` 指向下一段剧情。
4. 场景中的 `StoryManager` 持有一个 `startNode`，游戏开始时自动显示这个起始节点。
5. 玩家点击下一对话按钮时，`StoryManager` 会根据当前节点的 `nextNodeID` 查找并跳转；如果当前节点勾选了幕末返回普通模式，则会关闭 Story UI。
6. 玩家点击分支按钮后，`StoryManager` 根据分支配置跳转到对应的 `StoryNodeSO`。
7. 剧情推进过程中，系统会把当前节点 ID、已获得线索和剧情 flag 写入 `PlayerData`。
8. 每次进入新剧情节点时，系统会把节点 ID 记录到 `PlayerData.visitedStoryNodeIds`，用于上一对话和下一对话。

## 核心脚本

### StoryNodeSO

路径：`Assets/脚本/剧情线/StoryNodeSO.cs`

`StoryNodeSO` 是剧情节点的数据资产。它本身不控制 UI，也不处理按钮点击，只负责保存一段剧情需要的数据。

主要字段：

- `nodeID`：剧情节点唯一 ID。进入节点时会写入 `PlayerData.currentStoryNodeId`，用于记录当前剧情进度。
- `speakerName`：当前对话的说话人名称。
- `dialogueText`：当前节点显示的剧情文本。
- `cgImage`：当前节点显示的场景 CG 或背景图。
- `characterImageIndex`：当前节点显示的人物立绘索引。`StoryManager` 会从 StoryCanvas 上的 `characterSprites` 数组中按索引读取立绘；`-1` 表示不显示立绘。

当前建议的立绘索引：

- `-1`：不显示立绘
- `0`：小明
- `1`：父亲
- `2`：母亲
- `3`：陈爷爷 / 陈工
- `4`：陈奶奶
- `5`：陈春柏
- `6`：高中历史老师
- `7`：卫生所年轻医生
- `8`：疯疯癫癫的道士
- `9`：村民群像
- `10`：旁白
- `11`：树神 / 古神
- `nextNodeID`：下一段顺序剧情节点 ID，用于下一对话按钮。`StoryManager` 会根据这个 ID 在剧情节点表中查找目标节点。
- `returnToNormalModeOnNext`：幕末返回普通模式。勾选后，玩家在该节点点击“下一对话”时会关闭 Story UI，回到普通模式；适合每一幕最后一句。
- `rewardClue`：进入该节点时自动解锁的线索 SO。
- `flagOnEnter`：进入该节点时自动加入 `PlayerData.storyFlags` 的剧情标记。
- `isEnding`：标记该节点是否是结局节点。
- `endingType`：结局类型，例如真结局、普通结局、坏结局。
- `choices`：当前节点的分支选项列表。

### StoryChoice

`StoryChoice` 是 `StoryNodeSO` 中的单个分支选项。

主要字段：

- `choiceText`：显示在按钮上的选项文字。
- `nextNodeID`：玩家点击该选项后跳转到的剧情节点 ID。分支节点里的每个分支都应填写自己的跳转 ID。
- `requiredClue`：选择该分支需要拥有的线索。为空表示不需要线索条件。
- `requiredFlag`：选择该分支需要拥有的剧情 flag。为空表示不需要 flag 条件。
- `flagOnChoose`：玩家选择该分支后写入 `PlayerData.storyFlags` 的剧情标记。

### StoryManager

路径：`Assets/脚本/UI/StoryManager.cs`

`StoryManager` 是剧情系统的运行控制器，负责把 `StoryNodeSO` 的数据展示到 UI 上，并处理分支跳转。

运行逻辑：

1. `Start()` 中检查 `startNode`。
2. 如果 `startNode` 不为空，且当前没有正在显示的节点，就调用 `ShowNode(startNode)`。
3. `ShowNode()` 会把节点设置为 `currentNode`。
4. 如果场景中存在 `PlayerData.Instance`，会记录当前节点 ID，并写入节点的 `flagOnEnter`。
5. 如果节点配置了 `rewardClue`，会调用 `PlayerData.Instance.CollectClue()` 解锁线索。
6. 解锁线索后，会刷新 `ClueManager` 和 `PlayerManager` 的 UI 数据。
7. 然后把节点中的说话人、对话文本、CG，以及通过 `characterImageIndex` 查到的人物立绘显示到剧情 UI 上。
8. 最后调用 `RefreshChoices()` 刷新所有分支按钮。

分支选项 UI：

- 当前节点有 `choices` 时，`StoryManager` 会清空之前生成的选项按钮。
- 然后根据 `choices` 数量，在 `choiceParent` 下动态生成 `choiceButtonPrefab`。
- 每个生成出来的按钮会显示对应的 `choiceText`，点击后调用 `Choose(index)`。
- 有分支选项时，`choiceParentImage.color.a = 1`，父物体图片不透明。
- 没有分支选项时，`choiceParentImage.color.a = 0`，父物体图片透明。

顺序剧情按钮：

- `ShowPreviousDialogue()` / `PreviousDialogue()`：上一对话按钮绑定入口，会优先读取 `PlayerData.visitedStoryNodeIds` 中的上一条历史。
- `ShowNextDialogue()` / `NextDialogue()`：下一对话按钮绑定入口。如果当前处于回看状态，会先跳到历史中的下一条；否则跳转到 `currentNode.nextNodeID` 对应的节点。
- 如果当前节点勾选了 `returnToNormalModeOnNext`，且没有可继续前进的历史节点，点击“下一对话”会调用 `ReturnToNormalMode()`，关闭 Story UI。
- 如果上一条历史对应的是带有 `choices` 的分支节点，系统会输出 `Debug.Log("无法跳转")`，并停留在当前节点。
- 如果当前节点没有可用上一条历史或下一段，绑定的按钮会自动变成不可点击。

普通模式 / 剧情推进模式：

- 剧情推进模式：`StoryManager.ShowNode()` 会打开 `storyUI`，显示剧情节点。
- 普通模式：`StoryManager.ReturnToNormalMode()` 会关闭 `storyUI`。
- 每一幕最后一个剧情节点建议勾选 `returnToNormalModeOnNext`，让玩家读完最后一句后点击“下一对话”回到普通模式。

## 剧情历史如何保存

`PlayerData` 中有一组专门保存剧情历史的数据：

- `visitedStoryNodeIds`：玩家走过的剧情节点 ID 列表。
- `storyHistoryIndex`：当前正在显示的剧情节点在历史列表中的索引。
- `currentStoryNodeId`：当前剧情节点 ID。

普通推进剧情时，`StoryManager.ShowNode()` 会调用 `PlayerData.RecordStoryNodeVisit(node.nodeID)`，把当前节点 ID 加进历史。

如果玩家点击上一对话，`StoryManager` 会先读取 `visitedStoryNodeIds[storyHistoryIndex - 1]`。如果这个节点是分支节点，也就是该 `StoryNodeSO.choices.Count > 0`，则不允许跳回去，并输出：

```text
无法跳转
```

如果玩家先回看旧剧情，再点击新的下一段顺序剧情，`PlayerData.RecordStoryNodeVisit()` 会清除当前位置之后的旧历史，再把新节点加入历史，避免历史路线和当前选择冲突。

## 分支如何判断能否点击

每个分支按钮是否可点击，由 `StoryManager.CanChoose()` 判断。

判断规则：

- 如果 `requiredClue` 为空，说明该分支不需要线索。
- 如果 `requiredClue` 不为空，玩家必须已经在 `PlayerData.unlockedClues` 中拥有这个线索 SO。
- 如果 `requiredFlag` 为空，说明该分支不需要剧情标记。
- 如果 `requiredFlag` 不为空，玩家必须已经在 `PlayerData.storyFlags` 中拥有这个标记。
- 线索条件和 flag 条件都满足时，按钮才会变成可点击。

如果玩家点击了不可选分支，`StoryManager` 会调用 `PlayerManager.ShowTip()` 显示操作失败提示。

## 线索和剧情的关系

剧情节点可以通过 `rewardClue` 奖励线索。

进入节点时：

```text
StoryManager.ShowNode()
-> PlayerData.Instance.CollectClue(node.rewardClue)
-> ClueManager.RefreshData()
-> PlayerManager.UpdatePlayerUI()
```

线索真正保存在 `PlayerData.unlockedClues` 中，类型是 `List<ClueSO>`。后续剧情分支会通过 `PlayerData.HasClue(requiredClue)` 判断玩家是否拥有某个线索。

如果在 `PlayerData` 的旧版“已解锁线索 ID”里填了 ID，例如填入 `1`，需要确保 `ClueManager.allClues` 中包含 `clueId = 1` 的 `ClueSO`。`ClueManager` 启动和刷新时会尝试把旧 ID 数据同步成新的 SO 引用。

## 剧情 flag 如何使用

剧情 flag 是一个字符串标记，保存在 `PlayerData.storyFlags` 中。

常见用法：

- 在节点的 `flagOnEnter` 中填写一个标记，表示玩家已经进入过这个剧情节点。
- 在分支的 `flagOnChoose` 中填写一个标记，表示玩家做过某个选择。
- 在其他分支的 `requiredFlag` 中填写同一个标记，让该分支只有在满足前置剧情条件后才能点击。

例如：

```text
节点 A 的某个选项 flagOnChoose = talked_to_owner
节点 B 的某个选项 requiredFlag = talked_to_owner
```

这样玩家必须先在节点 A 做过对应选择，之后在节点 B 才能点击需要这个条件的选项。

## UI 绑定方式

在场景中的剧情 UI 对象上挂 `StoryManager`，然后在 Inspector 中绑定：

- `startNode`：剧情起始节点。
- `allStoryNodes`：当前场景可跳转的全部剧情节点。使用 `nextNodeID` 或分支 `nextNodeID` 跳转时，目标节点必须在这里。
- `storyUI`：剧情面板的 `UIControl`。
- `cgImage`：显示 CG 或背景的 Image。
- `characterImage`：显示人物立绘的 Image。
- `characterSprites`：StoryCanvas 上统一维护的人物立绘数组。剧情节点只保存索引，不再直接保存立绘 Sprite。
- `characterSpriteIndexNotes`：立绘索引注释，用于在 Inspector 中对照每个编号对应的人物。
- `speakerText`：显示说话人的 TextMeshProUGUI。
- `dialogueText`：显示剧情文本的 TextMeshProUGUI。
- `choiceParent`：动态生成分支按钮的父物体。
- `choiceButtonPrefab`：分支按钮预制体，预制体上需要有 `Button`，子物体中建议有 `TextMeshProUGUI`。
- `choiceParentImage`：类型是 `Image`，用于控制分支父物体图片透明度。可不手动绑定，运行时会从 `choiceParent` 获取。
- `choiceButtons`：旧的预放分支按钮列表。没有配置 `choiceParent + choiceButtonPrefab` 时才作为备用显示。
- `choiceTexts`：旧的预放分支按钮文本列表，和 `choiceButtons` 配套备用。
- `previousDialogueButton`：上一对话按钮。
- `nextDialogueButton`：下一对话按钮。
- `playerManager`：玩家 UI 和提示管理器，可不填，运行时会自动查找。
- `clueManager`：线索管理器，可不填，运行时会自动查找。

动态分支模式下，不需要提前摆好多个分支按钮，只需要绑定一个按钮预制体和一个父物体。备用的 `choiceButtons` 和 `choiceTexts` 仍要求顺序和 `StoryNodeSO.choices` 对应。

## 创建一段新剧情的步骤

1. 右键 Project 面板，选择 `Create/Game/Story Node` 创建剧情节点。
2. 填写 `nodeID`、说话人、剧情文本和画面资源。
3. 如果进入这个节点要奖励线索，把对应 `ClueSO` 放到 `rewardClue`。
4. 如果进入这个节点要记录剧情状态，填写 `flagOnEnter`。
5. 在 `choices` 中添加分支。
6. 如果这是顺序剧情，把下一段节点的 `nodeID` 填到当前节点的 `nextNodeID`。
7. 如果这是分支剧情，在 `choices` 中添加分支。
8. 如果这是某一幕最后一个节点，勾选 `returnToNormalModeOnNext`。
9. 每个分支填写按钮文字 `choiceText` 和跳转目标 `nextNodeID`。
10. 如果分支需要前置条件，填写 `requiredClue` 或 `requiredFlag`。
11. 如果选择分支后要记录玩家选择，填写 `flagOnChoose`。
12. 把第一段剧情节点拖到 `StoryManager.startNode`。

## 当前注意事项

- `isEnding` 和 `endingType` 目前主要是数据标记，代码中还没有专门的结局 UI 结算逻辑。
- 使用 `nextNodeID` 跳转时，需要把目标剧情 SO 放进 `StoryManager.allStoryNodes`。
- 动态分支模式不会受 `choiceButtons` 数量限制；备用预放按钮模式下，超出绑定按钮数量的分支不会显示。
- 如果某个选项没有配置有效的 `nextNodeID`，该分支按钮会不可点击。
